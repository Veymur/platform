# Polar diagnostic regression fixtures (D6)

`synthetic/` contains deliberately invented input. `hardware/` is reserved for reviewed, pseudonymized inputs captured with an actual sensor. Emulator injection is always **synthetic**, even when its ZIP was generated by the native Android exporter. No hardware fixture has been verified yet.

The D1 `synthetic/contract-examples.json` is a set of independent schema examples, not a capture or replay fixture. D6 `*.fixture.json` files have their own [fixture v1 schema](../schema/fixture-v1.schema.json). Each has a separately authored `*.expected.json`: input assertions, references explaining their basis and future recorder assertions. Recorded processing is evidence of what ran, **not the expected-result oracle**. Current tests execute the data assertions; recorder assertions await D7.

| Fixture | Retained inputs / processing | Purpose |
|---|---:|---|
| `synthetic/native-callbacks.fixture.json` | 21 / 21 | Native synthetic SDK callback inventory, repeated arrays, unusual HR, NaN bits, errors and backwards UTC |
| `synthetic/native-hr-focus.fixture.json` | 6 / 6 | Focus on sequence 6; preserve all five preceding inputs and explicitly mark the omitted suffix |
| `synthetic/native-interrupted.fixture.json` | 1 / 0 | Keep an unknown tail, null end/received count and missing processing |
| `synthetic/native-checkpoint-failure.fixture.json` | 1 / 1 | Keep `incomplete` and `checkpoint_persisted:false` despite an available committed input/processing pair |

The source SHA-256, original/requested/retained sequence ranges, schema fingerprints, converter version, counts and transformations are in each fixture's provenance. Original ZIPs remain local in ignored `artifacts/polar-diagnostic-d5/`; they are not copied here. Review transformed fixtures before sharing; pseudonymization does not make HR/timing patterns anonymous.

## Prepare and verify

From `apps/sensor` (Python standard library only):

```bash
python3 scripts/prepare_polar_fixture.py prepare /private/capture.zip \
  --kind synthetic --scenario hr-gap --from-sequence 6 --to-sequence 9 \
  --output /private/hr-gap.fixture.json
python3 scripts/prepare_polar_fixture.py check /private/hr-gap.fixture.json
python3 scripts/prepare_polar_fixture.py check /private/hr-gap.fixture.json --source /private/capture.zip
npm run test:diagnostics
npm test
```

`--kind` and `--scenario` are explicit. Kind is an operator declaration, not an automatic hardware attestation. Use `--kind hardware` only for an actual hardware capture. The scenario must be a short, non-identifying slug. Paths, original IDs, the ID map, phone metadata and conversion wall time are not put into the fixture. No file is staged in Git by this tool.

The converter validates a private snapshot of the **entire** ZIP with the D5 validator before selecting anything. It never changes the original or overwrites an output. A selected range is an input-sequence range, not a UTC range. Every available input before the focus is retained, with its linked processing, from the source's beginning. Initial configuration comes from capture metadata, retaining connection/session/pause/settings/active time/HR receipt time and exact HR age at the capture anchor. It is not an inferred state at the selected input. No new commands, processing, state transitions or measurements are invented.

The bounds are 256 retained inputs, 512 processing records and 1 MiB JSON output. A large required prefix fails explicitly; choose a smaller scenario. There is no option to discard history and guess state. Late processing past the last retained receipt and omitted suffixes remain explicit limitations. The source checkpoint retains its original counts and completeness; retained counts are separate. `null`/unknown tail and zero known losses do not imply that no data was lost.

Identifiers in envelopes, initial configuration, nested devices, command arguments and processing are mapped consistently. MAC/UUID/short-hex identity shapes are retained where applicable. Empty/nullable IDs stay empty/nullable. All non-empty free text (including error messages, stack names/paths, device-info values and unknown keys) is replaced, so embedded identifiers not found in typed fields are also removed. Empty strings/null, error graph links, scalar numbers/booleans/arrays, sequence, monotonic time and float bits survive. Standard Bluetooth characteristic UUIDs, fixed enums, known diagnostic fault codes and the three configured SDK features retain their meaning; custom UUIDs/features are pseudonymized. Device names become generic while preserving the native case-insensitive `Sense` predicate. These transformations can remove useful text distinctions from recorder output; expectations must reflect the declared transform, not the source text.

UTC defaults to a uniform shift aligning capture start to `1700000000000`. `--utc-start-ms` chooses another synthetic epoch; `--keep-utc` leaves original dates intact. All receipt, processing and capture UTC values receive the same offset, preserving intervals and clock jumps. Monotonic nanoseconds are not shifted. The reversible source offset is not published; provenance records the target/policy. Source-reproduction checks use the private original to recover the offset.

`check` verifies the fixture schema, input/processing schemas, references, ordering, counts, ranges, initial HR age, source knowledge and limitation flags. `check --source` additionally recomputes the conversion and compares its canonical content, reporting `source_reproduced:true`. Without the original, a structurally valid fixture does not prove correct pseudonymization/provenance. SHA-256 links to an original; it is not a digital signature or independent proof of operator-declared origin.

`replay_ready:false` is deliberate. D3–D5 command logging and the exact snapshot/sink activation boundary remain unresolved; even a structurally complete callback capture cannot prove replay completeness. D7 must introduce the actual native player/clock/effect adapters and compare against independently authored expectations. GPS/OS/disk scheduling are outside the first Polar replay scope.
